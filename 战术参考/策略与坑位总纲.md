## 一、一天的节奏

一天 = 白天 70 回合 + 夜晚 60 回合（任务书 §4.2），共 130 回合；一场 10 天 1300 回合。
**白天是准备，夜晚是结算**——白天没做完的事，夜里会以"基地掉血"的形式收账。

```
R1 ────────── 白天 70 回合 ────────── R70 │ R71 ──── 夜晚 60 回合 ──── R130
建塔 / 采掘 / 贩卖 / 做任务                机器人压境 / 守塔
                                            ↑ 天亮清场（清场不算击杀）
```

### 白天（每回合都在算的三件事）

1. **塔够不够三座？** 开局 75 金正好够 3 座（25/座，任务书 §4.5.1）。**R1 就要落第一座**
   ——复盘里敌方 R1 已经连建 2 座，我们 R4 才落第一座就是纯亏回合。
2. **石头够不够砌墙？** 墙只吃石头，一趟矿来回十几格。**人已经在矿区就把这批采满
   再走**：账很简单——在矿边多采 1 块 = 1 回合，回一趟矿 = 约 20 回合。
3. **天黑前回得来吗？** 距天黑 ≤25 回合才启动回防判断，按**步数**（不是直线距离）
   决定出不出发：围墙围起来之后"直线 3 格"可能要绕到缺口再进去、实际十几步。

### 夜晚（三个角色 = 三座塔）

- 机器人**全图可见**（任务书 §4.3），所以"来敌方向"是可以推的——见 §三.2。
- **首夜第 1 回合大概率 `manned=0`**：开拓者刚从任务点往回走、工人还在矿区。
  这是常态，不是故障；真正要抓的是"过了几个回合还没到位"。
- 一个角色只能发一条指令，**一回合只能操控一座塔**。三塔三人时"谁站哪"就是全部。

### 次日天亮

- 残余机器人天亮自动清除，**清场不算击杀**（任务书 §4.7.3）。
- 任务点冷却 30 回合，第 1 天接过的任务点通常在第 2 天白天就能再接。
- 夜里损失的塔要补（`MAX_TOWERS` 是全局上限 3，被打掉就空出名额）。

## 二、逐日策略

> **说实话**：客户端目前没有"第 N 天专用分支"——经济与防御是同一条优先级队列，
> 任务链路是同一条阶梯。下面写的是**每天实际会遇到的局面**与**当时的应对**，
> 以及哪些是"还没做、该做"的。

### 第 1 天（R1–130）

| 阶段 | 该做的事 | 客户端现状 |
|------|---------|-----------|
| R1–R3 | 连落 3 座塔（75 金刚好花完） | ✅ 优先级队列第 2 项 |
| R4–R20 | 开采：建造工采石、采集工采铜铁；开拓者走任务点（10 格 ≈ 9–10 回合） | ✅ |
| R20–R45 | 砌墙（目标 8 段）；卖矿换金币；任务链路跑第一轮 | ✅ |
| R45–R70 | **天黑前回防**（≤25 回合启动） | ✅ `dusk_recall` |
| R71–R130 | 首夜防守。实测机器人 `70[s60 m10 l0 b0]` | ✅ |

**首日的坑**：见 §五.2——首夜三塔只开两座、围墙把塔封死，两条都是第 1 天就该
出事、而且**只在第 1 天夜里看得出来**的。

### 第 2 天（R131–260）

- **升级**：3 塔齐了之后金币的下一站是武器升级券（100 / 150 金）。塔升一级
  射程与攻击力都上台阶（加特林 3→5→7，火箭 10→15→全图）。
  ⚠️ **现状是"金币卡在 41 不动"**：见 §五.3 的卖矿触发条件缺口。
- **补墙**：夜里掉了几段补几段。
- **再做任务**：任务点冷却期满，同一个点能再接。
- **夜间机器人变多**（任务书 §4.7.3：数量随天数增加），大型/BOSS 开始出现，
  它们的 HP 是 500 / 800（小型才 40）——**目标选择开始有意义**（先打大的）。

### 第 3 天及以后

- 每多一天，夜间的机器人更多；防线要跟着从"三塔 + 8 段墙"往"升级塔 + 补墙"走。
- 任务点每 30 回合刷新一次，**一场 10 天大约能接 10+ 次任务**——这是与对手拉开
  分差最大的一条线（单次 80 分，10 次就是 800 分，而击杀分要靠打几百只机器人）。
- ⚠️ **还没做**：目前没有"随天数提升防线"的分支（比如第 3 天起主动买升级券、
  第 5 天起改变塔的配比）。**这是下一步最值得补的空白。**

## 三、四条线的策略

### 3.1 经济（`strategy/economy.py`）

**专职分工，不切换。** 建造工（id 小的工人）管塔与墙，采集工管矿与卖。
V1 的"采集中断 9 回合"就是分工来回切造成的。

**优先级队列**（建造工）：用升级券 → 塔未满 3 座就建塔 → 修墙包 → 砌墙 →
买升级券（金币 ≥100）→ 采石。

**采集工**：有小贩按收购价采（铜 5 > 铁 3 > 石 1）；**没有小贩只采石**——
铜铁的唯一用途就是卖给小贩，没小贩就是纯负重，而墙只有石头能砌。

**卖矿的唯一判据**（`sell_now`）：出发判断与"到了跟前卖什么"必须共用同一个函数。
分成两套会打架——出发时认为"没钱必须卖"，走到跟前又发现"这块石头要留着砌墙"，
于是原地折返，下一回合又出发。实测工人就这么在 `(22,14)↔(21,15)` 踱了 6 个回合，
**一块石头从采到砌上花了 28 个回合**。

**围墙批量采石**：`STONE_BATCH = 6`。采 1 块回一趟 = 13 回合 1 段墙，采满一批
再回 = 1 段/2 回合。

### 3.2 防御（`strategy/defense.py`）

**塔位由基地位置现算 + 在线学习可建造区**，换边自动跟着平移。三条判据：

1. 只用语料确证过能建的偏移（`world.zone()` 学到 `True` 的）；
2. **建成预演**：假设三座塔都建好，每座旁边还得有一格能从基地走到
   （`layout_ok`）——对应"炮塔把路堵住然后有一个炮塔碰不到"这个坑；
3. 取"离基地最近、最朝来敌方向"的组合。

> 试过"把塔摊开"（打分偏好两两不相邻）——**实测更差**：三种来敌方向下稳态都从
> 3/3 掉到 2/2。塔要靠人操控，摆得开不等于守得住，人走过去是要花回合的。

**来敌方向：每回合从报文推，不写死。** 敌基地全图可见（接口文档 §1.4），
用它和我方基地的连线算方位。两个出生基地在地图对角，**连线几乎总是斜的**，
所以要按"离来敌方向多远"排名次：

```
正对来敌的那一面  >  两翼（垂直方向）  >  背面
                    ↑ 两翼必须并列
```

**围墙**（第二圈，半径 2）：够盖住来向 + 两侧即可，8 段。两条硬约束：

- **不建在已占用的格子上**（塔在 `ours` 里，不在 `mapInfo.zones` 里，只查 zones
  会以为那格是空地）；
- **不让任何一座塔的落脚点少于 2 个**。只留 1 个的话，一台机器人堵上去这座塔
  就哑了。**边选边验**——事后砍掉墙段等于把来敌方向的防线让开。

**夜间配位**（三人三塔）：

1. **整体指派**，不是逐个贪心。贪心挑"单个最优"会漏掉"加特林离两人都只有 1 格、
   而开拓者除了加特林哪座都去不了"这种局面。
2. **可达性要算，而且要把机器人算成障碍**。任务书 §4.1 规定机器人与角色都阻挡移动。
3. **走不到就换塔**，不是原地站着。换塔时"已被占"的集合只装**已经有人到位、
   真的在开火**的塔——装"所有已配对的塔"的话，三塔三人时最后一个人看到的就是全集，
   换塔那条路直接死掉。

### 3.3 自进化任务（`strategy/task/`）

**族识别吃侦察输出的原文。** `phaseTask` 实测只有 27 字节、一个关键词都没有
（"请阅读task_1_beijing.md，获取任务信息"），真正的族信号在沙盒回包里：任务目录名
（`1-unknown-api` / `2-engineering-fix`）、`API_DOCS.md`、`spec.md`、`ws_1`、`./check`。

**阶梯必然推进。** 每回合结束前要么拿到答案进提交、要么让步骤前进或 `repeats` 增加。
不存在"这一回合什么判断都没命中，于是把上回合的命令原样再发一遍"。

**错误驱动发现（"文档过时"那一族的通解）。** 客户端**不预置任何接口知识**：

```
按文档的候选打一轮 → 读 401/400 的响应体 → 抽出它点名要的头/参数
      → 补进候选（插到最前）→ 再打一轮
```

实测那道题 10 次调用收敛。把服务端换成用 `X-Auth-Token` + `province`
（两个名字文档里都没有），同一段逻辑照样收敛（`tests/test_tasksandbox.py`）。

**答案闸门**（`answer.py`）：唯一允许产出 `submitAnswer` 的地方。拒绝文档回声、
错误体、空壳；**接受部分正确**——任务书 §6 规定部分完成按通过率给分，
"交一份对了一半的答案"严格优于"不交"。

**止损**：`ladder_exhausted` 意味着确定性阶梯 / LLM 兜底 / 通用探测**三条路都没走通**，
那是**客户端自己**的故障，不是某个任务点的性质。换个任务点大概率同样走不通——
所以放弃后抑制 15 回合不再接，把角色还给经济与防守。

### 3.4 编排与异常预算（`brain.py`）

- **一个角色一回合只能有一条指令**，按 `任务 > 建造/采集 > 防御移动` 消解冲突。
- **`hold` 语义**：任务中的开拓者原地驻守——离开任务点一格内即视为任务结束。
- **兜底粒度必须停在任务链路上**：任务失败只是"这一回合不推进阶梯"，采集/建造/
  回防照常。实测过一次任务子系统抛异常被最外层兜住，变成**整个回合的空指令**，
  连续 9 个回合三个角色一次都没动。
- **异常预算**（任务书 §8）：单队累计 5 次异常就整场不再调度。所以宁可少发一条
  指令，也不发字段不全的指令。

## 四、日志与复盘

**stdout 是对局结束后唯一的取日志手段。** 判题系统采集的是进程 stdout，
`debug.log` 只服务本地——所以**任务的全量信息一律走 INFO，一字节都不精简**：
`execute_cmd` 的脚本正文、沙盒原文、提交的答案都在那里。

> 走过一次弯路：因为两份日志都在 ~180–200KB 处从记录中间截断，判断"被采集上限
> 截断"，就把脚本正文压到 DEBUG 省体积。**补充后的完整日志有 592KB 且完整收尾**
> ——根本没有上限，那两次"截断"是抓取时对局还没跑完。已全部回退。

每回合固定三行 + 事件行，全部单行 `key=value`：

```
request_decoded   决策前的状态快照（含 neutral= 的坐标、chars=、bag=）
strategy_done     本回合下发了什么 / 花了多少 / 失败回执
round_end         相对上一回合的增量（击杀/掉血/损失/空转）
task_event        任务链路的状态变化（只在转折点打）
task_dump         任务全量转储（题面/命令/回包/答案/内部状态），只碰任务的回合才有
```

读法与字段对照见 [日志分析模板V2.md](./日志分析模板V2.md)。三个最容易看漏的点：

- **`manned` 数的是"有人站在旁边"，不是"这座塔打了"**。三塔三人时它长期报 3，
  而实际可能只有 2 座在开火——真正的判据是 `strategy_done actions` 里的 `:attack` 条数。
- **`request_decoded tasks=`** 的 `可接` / `/冷却N` 是判断"开拓者该不该在任务点蹲着"的
  唯一依据。
- **`neutral=` 带坐标**——工人在某一格来回踱步时，把它的目标格和 `stone[12,3]` /
  `vendor[20,15]` 对一下就知道是在去干活的路上，还是在自己绕圈。

## 六、怎么验证（改完代码跑什么）

```bash
cd CoreGeek

python -m pytest tests/ -q              # 346 个用例
python tools/tasksandbox/run.py         # 13 道自进化题（A 族 7 城 + B 族 6 变体）
python tools/local_check.py             # 真实报文 + 边界 + 1300 回合性能
python tools/nightsim.py --spread       # 夜间开火：稳态必须三塔全开
```

| 工具 | 回答什么问题 | 判据 |
|------|------------|------|
| `pytest` | 有没有把别的地方弄坏 | 全绿 |
| `tasksandbox/run.py` | **照现在这份代码，题做得完吗** | A 族 `[ANSWER]` 与标准答案逐字段相同；B 族 `./check` 通过且客户端抓到 TOKEN |
| `local_check.py` | 报文格式/边界/性能 | 单回合 < 1s（当前 ~2.5ms） |
| `nightsim.py` | 三塔是不是都在开火 | 稳态每回合 3 发 |

**判据是判分口径，不是"跑完不报错"**——这一点很关键：
`tasksandbox` 里还有两类**守题**用例，题目不修就过不了（否则"通过了"没意义）、
手工修好一定过得了（否则"做不完"是我们的实现问题）。以及一条"宪法"：
**事实区开局必须是空的**——客户端不许预置这道题的答案。
