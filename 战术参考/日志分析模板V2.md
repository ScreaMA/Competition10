## 零、先看这几条

1. **每条结论都要能指到具体字段。** 写"金币冻结"要给出
   `R8-R16 round_end` 或者 `freeze_alert` 那一行；写不出字段的结论等于猜。
2. **敌方信息天生残缺。** 接口文档 §1.4：`teamEnemy` 只有 `roles`，且只有基地
   与围墙全图可见。`enemy_towers=0` 既可能是"真没有"也可能是"没看见"——
   用 `enemy_visible` 区分，不要当成事实。
3. **模板里 `{待人工}` 的格子不是"可以跳过"**，是"日志给不出、必须读原文或
   看回放才能填"。填不了就在 Issue 里**明说填不了**，不要编。
4. **V2 的模块地图变了**：报告里写 `brain.py` 会让自动修复找不到落点，
   对应模块按第 7.1 节的表填。

## 一、日志格式速查

每回合固定三行，加事件行。全部单行、`key=value`、无嵌套。

### 1.1 `request_decoded`（决策前的状态快照）

| 字段 | 含义 | 用在哪一节 |
|-----|------|-----------|
| `round` / `day` / `tod` / `round_in_day` | 绝对回合 / 第几天 / day\|night / 当天第几回合 | 元信息、§五 |
| `team` / `team_id` | 阵营（challenger/defender）/ 队伍 ID | 元信息 |
| `gold` / `gold_delta` / `score` | 金币 / 相对上回合变化 / 累计积分 | §二 |
| `base` | 基地 footprint 原点坐标 | §三 |
| `hp` | 基地 `当前/满血`（满血按任务书 §4.5.1 的等级表） | §一 |
| `towers` | `3[rocket1@9,25 railgun1@10,25 gatling1@9,24]` | §一、§三 |
| `walls` | `5[l1:3 l2:2]`（段数 + 等级分布） | §一、§三 |
| `robots` | `4[s1 m1 l1 b1] near=9@20,24`（构成 + 离基地最近那台） | §五 |
| `enemy_visible/towers/walls` | 视野内的敌方单位数 / 其中塔、墙 | §一 |
| `neutral` | 中立元素清单 `stone:6,iron:4,copper:4,vendor:1,weaponShop:1,…`。**先看有没有 `vendor`**：没有小贩 = 卖不出矿 = 金币再也回不来 | §二 |
| `tasks` | 每个任务点：`类型@坐标 可接/冷却N /超时N回/N分` | §四 |
| `phase` | 当前已领取任务的原文（截断 60 字） | §四 |
| `task` / `plan` | 任务链路本回合的动作 / 它的说明 | §四 |
| `chars` | 三个角色的位置 `10010@5,23 10011@10,12 10012@10,16` | §五 |
| `bag` | 背包（重复物品压成 `copper×21`） | §二 |
| `zone` | 可建造区学习进度 `weapon=3/0 wall=2/1`（已确证可建 / 已确证不可建） | §三 |

### 1.2 `strategy_done`（本回合下发了什么）

| 字段 | 含义 |
|-----|------|
| `commands` / `elapsed` | 指令条数 / 决策耗时（毫秒） |
| `gold_spent` | 本回合**理论**支出（按任务书价格表算）；与下回合 `gold_delta` 不一致 = 有指令被拒 |
| `actions` | 每条指令：`角色ID:动作→落点 [名称/型号]`，attack 会带**机器人型号** |
| `fail` | 上回合被判"执行失败"的指令，形如 `10010:build`（`角色:动作`） |
| `sandbox` | `下发` / `空闲`：本回合有没有发 `executeCmd` |
| `note` / `learn` | 任务链路的内部说明 / 本回合学到的可复用事实 |

### 1.3 `round_end`（相对上一回合的增量）

| 字段 | 含义 |
|-----|------|
| `kills` / `kill_score` | 本回合击杀 `3(s1 m1 l1 b0)` / 折算积分。**天亮清场不算击杀** |
| `station_damage` | 基地本回合掉的血 |
| `towers_lost` / `walls_lost` | 被摧毁的塔 / 墙 |
| `weapons` / `manned` | 塔总数 / 其中有人站到旁边的 |
| `idle_weapon` | **没人操控**的塔数 → 回防/配位问题 |
| `idle_target` | 有人操控但**射程内没目标**的塔数 → 塔位/射程问题 |
| `idle_units` | 本回合没拿到任何指令的角色数（`idle_ids=` 给出具体 ID） |

> 白天 `manned/idle_weapon/idle_target` 打 `-`：角色白天本来就该去干活，
> 没人站岗不是问题。

### 1.4 `task_event`（任务链路的状态变化，只在转折点打）

`event` 取值与含义：

| event | 含义 | 重点看 |
|-------|------|-------|
| `accept` | 开拓者在任务点领了任务 | `detail` 里的任务点、超时、积分 |
| `start` | 任务正式开始（`phaseTask` 到达） | `key` 是族签名，`detail` 里的 family 与识别证据 |
| `step` | 推进到下一步 | `detail=advanced=<上一步> reason=<ok/repeat/capped/slow>` |
| `learn` | 学到可复用事实 | 接口地址 / 鉴权 / 参数名 / 字段映射 |
| `submit` | 提交了答案 | `detail` 里的 `answer_len` |
| `gate_reject` | 答案被闸门拦下 | `detail` 是原因（`doc_echo` / `error_body` / `type_mismatch`…） |
| `abandon` | 放弃任务 | `detail` 是原因（`deadline` / `ladder_exhausted` …） |
| `skill_saved` | 技能入库（自进化的关键证据） | `detail=steps=N` |
| `done` | 任务结束 | `submitted=` / `rejected=` |
| `rewind` | 答案被判错，回退到取数步骤 | — |
| `llm_exec` | 执行了 LLM 给的兜底命令 | — |
| `sandbox_slow` | 上一回合沙盒命令超时被掐断 | — |

### 1.5 `day_summary` / `freeze_alert`

```
day_summary day=1 rounds=1-130 kills=23 kill_score=31 station_damage=210
            gold_peak=120 gold_in=180 gold_out=150 build=8 upgrade=2 sell=14
            task_accept=2 task_submit=3 sandbox=24 commands=364 idle_units=32

freeze_alert round=200 gold=0 stalled_rounds=20 bag=10012{stone×3}
```

`freeze_alert` 是**条件触发**的：连续 ≥20 个回合 `gold < 25` 且没有任何支出
（建造/购买）才打一次。它就是 V1 报告里"金币冻结 9+ 回合"那条结论的自动版。

### 1.6 `task_dump`（自进化任务的**全量**日志，INFO 级）

**只要这一回合碰到任务**（有任务在身 / 下发了沙盒命令 / 收到沙盒回包 /
领任务 / 交卷），就额外打一组全量转储——上面那些 INFO 行是给复盘按字段读的、
一律截断压行，**排查任务问题要看的是这里的原文**：

| kind | 内容 | 回答什么问题 |
|------|------|-------------|
| `phase_task` | 当前任务描述的**全文**（INFO 里只有 60 字） | 题面到底要求什么 |
| `execute_cmd` | 本回合下发给沙盒的**完整命令**（含脚本全文） | 我们到底发了什么 |
| `last_cmd_result` | 沙盒**原样**回的内容（`[RECON]`/`[API]`/`[ANSWER]`…全文） | 沙盒到底回了什么 |
| `llm_prompt` | 发给 LLM 的 prompt 全文 | 兜底问的是什么 |
| `llm_resp` | LLM 回复全文 | 兜底答的是什么 |
| `submit_answer@<ID>` | 提交的答案全文（INFO 里只有 `submitAnswer(98B)`） | 交了什么 |
| `run_state` | 任务链路的内部状态 + 技能库 | 这一步试了几次、重复几次、交过/被拒过什么、技能库里有什么 |

- **走 INFO：stdout 与 `debug.log` 各一份。** 判题系统采集的是进程的 stdout，
  `debug.log` 只服务本地工具——只写文件的话，对局结束后容器里的日志拿不出来。
- **换行转义成字面量**，`--full` 负责还原成多行：stdout 那边可能被别的工具
  按行读，压成一行最保险。
- **单条上限 200KB**（环境变量 `TASK_DUMP_LIMIT` 可覆盖）：沙盒单次输出本身就被
  判题器截到 64KB；如果判题器侧的 stdout 采集限制更小，把它调小。

```bash
cd CoreGeek
python tools/analyze_log.py --full                    # 任务全量日志（还原成多行）
python tools/analyze_log.py --full --rounds 8-12      # 只看某几个回合
```

> 写复盘时的用法：**§六 日志原文里贴的应该是 `task_dump` 的内容**，不是
> INFO 那一行的截断版。INFO 行只用来定位"哪几个回合要看"。

## 二、症状 → 字段对照（复盘时最先查这张表）

| 报告里常见的说法 | 看哪个字段 | 判据 |
|----------------|-----------|------|
| 任务接取后从未提交 | `task_event` 序列 | 有 `event=start` 但没有 `event=submit` |
| 沙盒反复重读同一份文档 | `task_event event=step` | `detail` 里出现 `reason=repeat`，或长时间没有 `step` |
| 读题成功但从不调 API | 本轮 V2 已不可能（query 一步做完）；若真出现，看 `event=step` 的 `reason=capped` | — |
| 答案被交成文档原文 | `task_event event=gate_reject` | `detail` 含 `doc_echo` / `error_body` |
| 任务 2 全程可接未接 | `request_decoded tasks=` | `tasks=` 里长期有 `可接` 而 `task=idle`/`travel` |
| 金币冻结 | `freeze_alert` / `gold` 序列 | 报警行，或 `--template` 的金币曲线长时间贴 0 |
| 背包攒着矿石不卖 | `neutral=` 里有没有 `vendor` | **没有 `vendor` = 卖不掉**，不是调度问题；此时采集工应改采石（`MINER_ORDER_NO_VENDOR`） |
| 围墙迟迟不起 | `§1.3 围墙变化` + `bag=` | 一趟矿只带回 1 块石头 → 看 `strategy_done actions` 里连续 `collect` 的次数 |
| 采集断档 | `strategy_done actions` | 连续多个回合没有 `:collect` |
| 围墙不成型 | `request_decoded walls` + `§1.3 围墙变化` | 段数长期不涨 |
| 塔位堵路 | `strategy_done fail` | 反复出现 `ID:build` |
| 三塔贴基/同侧 | `request_decoded towers` | 直接看坐标是否分散、是否朝来路 |
| 三塔零升级 | `day_summary upgrade=` / `actions` | `upgrade=0` |
| 武器空转 | `round_end idle_weapon` | 夜里长期 > 0（有人没到位） |
| 射程不足 | `round_end idle_target` | 夜里长期 > 0（到位了够不着） |
| 目标选择不合理 | `strategy_done actions` | `attack→(x,y)` 后面带的型号：有没有先打 BOSS/大型 |
| 角色整回合空转 | `round_end idle_units` / `idle_ids=` | 夜里 > 0 |
| 开局建造延迟 | `§1.3 塔的建成顺序` | 首塔回合数 |
| 基地被平推 | `round_end station_damage` + `hp` | 掉血集中在哪几回合 |
| 指令被拒 | `strategy_done fail` + `gold_spent` vs 下回合 `gold_delta` | 两者对不上 |

## 四、对应模块怎么填

报告里要写"改哪个文件"时按这张表填。V2 已经把 V1 的 7114 行 `brain.py`
拆成 10 个模块，**写 `brain.py` 会让自动修复找不到落点**。

| 症状 | 模块 |
|------|------|
| 任务：阶梯顺序 / 止损 / 调度 / 提交与放弃 | `strategy/task/solver.py` |
| 任务：沙盒命令本身（取数、鉴权、分页、聚合） | `strategy/task/scripts.py` |
| 任务：答案校验（闸门） | `strategy/task/answer.py` |
| 任务：族识别 / 技能签名 / 技能生成 | `strategy/task/skills.py` |
| 任务：跨任务记忆（事实、技能库） | `strategy/task/memory.py` |
| 任务：沙盒输出解析 / 指纹 | `strategy/task/sandbox.py` |
| 经济：采集 / 贩卖 / 建造执行 / 金币分配 | `strategy/economy.py` |
| 防御：塔位 / 墙线 / 夜战火力 | `strategy/defense.py` |
| 世界模型：可建造区学习 / 敌方来向 | `world.py` |
| 寻路 / 可达性 / 锥形判定 | `grid.py` |
| 报文字段 / 指令构造（合法性、异常预算） | `protocol.py` |
| 日志字段 / 逐回合增量 | `brain._log_turn`、`telemetry.py` |
| HTTP 服务 / 决策超时保护 | `server.py` |

## 五、和历史版本的差异

| 项 | V1（[对战分析模板.md](./对战分析模板.md)） | V2 |
|----|------|-----|
| 日志来源 | `server.py` 的 brief 函数 | `brain._log_turn` + `telemetry.py` |
| 击杀 / 掉血 / 建筑损失 | 靠人工比对相邻两行（报告里大量"日志未覆盖"） | `round_end` 直接给增量 |
| 任务链路 | 只能从 `actions=` 反推，看不出"卡在哪一步" | `task_event` 给完整时间线（start/step/submit/abandon/skill） |
| 武器空转 | 只能数 `attack` 条数 | `idle_weapon`（没人到位）与 `idle_target`（够不着）分开 |
| 金币冻结 | 人工扫 `gold` 序列 | `freeze_alert` 自动告警 |
| 建造失败原因 | `fail=[ID]` 只有 ID | `fail=[ID:动作]` |
| 剧情口径 | "日志未覆盖"很常见 | 每个 `{待人工}` 都能指到"报文里确实没有"或"要读原文" |
| 模块名 | `brain.py`（7114 行） | 10 个模块，见 §四 |

> V1 的那份模板保留作历史存档；**新报告一律用本模板**。
